# Routine Trivial / Small work

Use this compact route for a single current/manual agent, after explicit selection. It replaces preloading the four full skill bodies for this route; it does not waive product rules, required reviews, tests, claims or merge authority. Read the selected entry, task guard, M `core.md`, [grade rules](sdd/grade.md), actual P sources, applicable project declarations and the declared tracker adapter once. Reuse unchanged inputs in the same session. Do not preload Medium/Large design procedures or packet/delegation documents.

## Eligibility and scope

- Confirm every Trivial condition, or one-module Small with no automatic escalation, using the grade rules and P's mapping. Re-evaluate when scope/risk changes. Never lower an automatic grade yourself.
- Apply model denies and explicit qualification requirements. The routine current/manual exception is in [execution routing](../skills/_shared/execution-routing.md#two-axis-routing). It does not permit automatic model selection or delegation. If required independent review, unresolved authority, another actor, or a higher-risk phase is involved, read that action's full skill/contract before proceeding; stop only dependent work.
- Confirm required verification, product edit paths, record location and scratch/build-output paths before writes. Temporary scripts, message files, caches and compiler outputs are writes too. Follow [task guard](../task-guard.md); a writable OS temp directory is not permission.
- Map the intended edits and verification in one sentence or short list under M's [ordered changes](../../methodology/supports/ordered-changes.md). No separate plan document, SDD, diagram or HTML is needed unless its actual trigger applies.

## Execute once, record once

1. **Work item.** Apply [priority decision and required body/labels](issue-priority.md) and the [evidence recording rules](issue-writing-guide.md#evidence-recording-rules). Use short content under the existing sections; do not copy the conversation. Keep testable acceptance criteria and actual allowed/forbidden paths. Search only for relevant duplicate/current work. Re-read the created item for correctness.
2. **Lane and claim.** Check repository/remote, dirty state, branch/worktree conflicts and competing claims before edits. Fetch the declared base branch and immediately capture `git rev-parse --verify 'FETCH_HEAD^{commit}'`; use that exact SHA. A single isolated clone can use a task branch without another worktree; concurrent lanes require isolated worktrees. Apply the tracker mapping for exclusive claim acquisition and owner/status updates, then re-check conflicts. Preserve other owners' state. Put start facts in this existing CLAIM record: task/W/base identity, sources actually read, record/scratch location and applicable support. No separate START comment is required. Check a linked prior observation, or at most one related closed item; record absent/unavailable without a history survey.
3. **Change and verify.** Edit only claimed paths. Test the owning module first; perform every P/Issue-required check on the final candidate and widen on evidence. A Trivial change uses a targeted check appropriate to the change. Self-review scope, acceptance criteria, failures and risks. Reuse PASS only for unchanged verified inputs; do not treat missing or failed checks as PASS. Do not create a second mapping, plan or packet for the same actor and unchanged task.
4. **Summary.** Write one `[IMPLEMENTATION SUMMARY]` with closing reference, branch/head/base, AC-to-result mapping, actual commands/results, self-review, remaining risks and the start/claim reference. Add the model line from [observations](observations.md#recording-the-authoring-model) using already available host/human metadata. Missing model/cost information stays `unconfirmed`/`not collected`; do not search host transcript/config directories merely to fill optional telemetry. Preserve actual incidents and their initial failure plus action/result; omit empty incident lists and repeated normal-step narratives. Fixed start facts are referenced, not copied.
5. **Merge and close.** Re-query current metadata immediately before merge, verify the declared target/mergeability and required checks, and honor P's merge authority. After authorized merge, fetch the declared target again and verify the actual merge according to the tracker adapter (including squash/rebase identity rules). Only then close the matching item. Re-read the durable start/summary once, preserve any worktree-only evidence, and record `[PRODUCT COMPLETE]` with the actual identities required by [finishing](../skills/finishing-issues/SKILL.md#6-merge-confirmation-and-release). Its unavailable observation-check line is non-blocking. Keep merge, close, product-complete and release markers separately identifiable, but they may share one existing closing update if the tracker supports it and their real order/identity is retained. For append-only trackers, add final facts there instead of duplicating the unchanged full SUMMARY.
6. **Cleanup and release.** Inspect uncommitted/untracked/ignored content and other worktrees before deleting only task-owned lane/branch artifacts authorized for cleanup. Keep durable records and required evidence. Re-check claim ownership while holding the exclusive claim, record release and clear only this owner's metadata, then remove that claim last. Never release a competitor's claim or report cleanup complete when it failed. End this task's scope; another task needs a fresh selection/session.

## Leave the compact route when needed

Use the relevant full skill/contract for a competing claim, synchronization/base change, changed acceptance criteria, required independent review, SDD, actual unresolved instruction/authority conflict or escalation. Existing [verification](verification.md), [parallel-development](../skills/parallel-development/SKILL.md) and [finishing](../skills/finishing-issues/SKILL.md) conditions still govern those actions. Reuse confirmed unchanged evidence instead of restarting all preparation. Do not resolve a conflict by silently dropping a requirement.
