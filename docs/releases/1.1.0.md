# v1.1.0 — 2026-11-07

Stable release: [v1.1.0](https://github.com/seok-jun/adaptive-agentic-sdd/releases/tag/v1.1.0). Includes [PR #16](https://github.com/seok-jun/adaptive-agentic-sdd/pull/16) and the release PR that carries this record. The immutable tag identifies the final release commit; v1.0.2 remains unchanged.

This is a minor release because the distribution changes what a Small task must read and record.

## Changes

**Small keeps Medium's safeguards and gets Trivial's paperwork.** Small is still a behavior change inside one module. Safeguards are the same as before: grading and escalation, owning-module tests first, required checks on the final candidate, claims, merge authority and human-decision stops.

- [`small-work.md`](../../adaptive-sdd/workflow/process/small-work.md) now names a closed reading set for Trivial/Small. Other common documents are opened only on its listed exception triggers.
- A normal Trivial/Small task writes three records: CLAIM, IMPLEMENTATION SUMMARY and CLOSED. CLOSED groups merge, closure, product completion, cleanup and release as labelled fields. The local-docs and GitHub adapters define those fields and their order.
- These now apply to Medium and above only: prior-observation searches, routine model lines, a methodology judgment at every close, the placeholder for unavailable checks, routine token checkpoints and the 150-character split rule.
- On GitHub, a compact CLAIM ends either with a terminal `CLOSED.release`, or, after escalation out of the compact route, with a full-procedure `[RELEASE]` that names the compact CLAIM.
- Unchanged: Medium/Large procedures, the grade rules, the resolver and the legacy installer.
- Both editions, all four skill entries, behavior eval cases and grader calibration were updated to match.

**Distribution consistency.**
- The workflow README describes the project-owned, editable W first and the legacy `install.py` copies after it.
- `observations.md` identifies the common source by the resolver's W commit; `install.lock.json` applies only on the legacy path.
- The adoption guide recommends Git 2.38+ for the local-docs merge check, with a worktree fallback.

**First use** ([PR #16](https://github.com/seok-jun/adaptive-agentic-sdd/pull/16), from zero-context newcomer runs):
- The README shows a separate Windows command and defines P, W and M where they are first used.
- START-HERE asks to allow local Git operations and claim-file deletion, and prints the Windows resolver command for both PowerShell and Bash.

## Verification and limits

- Windows: all 123 executable tests passed on the release tree. All five manifests match their files, and `git diff --check` passed.
- Independent read-only Codex reviews (`gpt-6-astra` / high) of the Small redesign found seven issues, then one more on re-review. All eight were fixed before this release.
- [Before/after runs](../eval-results/2026-11-07-small-redesign/README.md): three Codex runs per version of the same planted Small task. All six completed through merge, closure and claim release.
  - Records fell from 7 to 3, and the Records section from 107 to 57 lines.
  - Command output returned to the agent fell by a third, and every after-run read the same 14 workflow files.
  - Input tokens fell 8%. Wall time showed no difference.
- Known limit: the fixed reading set is still about 23k words for a one-line fix. Shortening it is left for a later release.
- No outcome, rework or cost experiment in a real project was run.

## Adoption

Existing project-owned W is not updated automatically. To adopt the lighter Small route, compare your W's `small-work.md`, the tracker adapter you use and the other workflow files this release changed against this tag, and merge what fits under project authority. New users can start with the try sandbox from the [README quick start](../../README.md#quick-start).
