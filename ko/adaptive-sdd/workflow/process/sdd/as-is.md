# SDD as-is

사람용 현황은 기존 `README.md`, 이 파일의 규칙으로 작성한 `01-as-is.md`는 상세 근거다. 최초 배치에만 [산출물 구조](../sdd-artifacts.md)를 확인한다.

### `01-as-is.md`

사람이 판단할 문제·원인 모델·현재 관계·위험은 `README.md`가 원본이다. 이 파일은 그 판단의 직접 근거를 소유한다.

- 현재 동작과 확인하지 못한 사실을 구분한 Agent evidence
- 확인한 코드 경로와 심볼
- 재현 또는 검증 근거
- 문서와 코드가 다르면 drift 항목

작성 순서는 사실/가설/미조사 → 직접 근거로 잡는다. 구체적인 표현이 필요할 때만 W의 [AS-IS 합성 예시](../visual-writing-examples.md#sdd-as-is)를 참고한다. 예시의 가상 사실을 실제 제품 근거로 사용하지 않는다.

#### 판단에 필요한 조사

사람의 선택이나 다음 작업의 전제를 좌우하는 항목에만 아래 조사를 적용한다. 상위 분석의 유효한 근거를 재사용하며 전수 이력 조사나 별도 분석 문서를 요구하지 않는다.

| 판단 상황 | 확인할 근거 |
| --- | --- |
| 기존 구현을 기준으로 이관·통합 | 이름과 실제 식별자, 활성 진입점, 확인한 revision 및 최근 운영 근거의 대응. 코드상 활성과 실제 운영 사용을 구분 |
| 구현 차이·비활성화 이유가 선택에 영향 | 관련 도입/변경 이력·티켓과 의도 근거의 유무. 작성자·시점만으로 의도를 확정하지 않음 |
| 외부 라이브러리·프레임워크 동작에 의존 | 실제 의존 버전의 소스·배포물/bytecode·공식 문서 또는 허용된 최소 실행. 다른 버전의 설명을 적용 근거로 사용하지 않음 |
| 데이터·로그·endpoint·전환 방식을 변경 | 직접 연결된 외부 호출자·운영 소비자·관측 방식과 그 정보의 원천·확인 시점. 코드에 없다는 이유로 소비자가 없다고 추정하지 않음 |

사람에게 선택을 묻기 전에 범위 안에서 확인 가능한 사실은 먼저 확인한다. 남은 불확실성은 확인한 근거·접근 실패·실행 필요·외부 확인 필요와 그 결론이 필요한 단계를 함께 적는다. 탐색을 무한 반복하거나 권한 밖 운영 조회를 하지 않고, 필요한 외부 사실만 사람에게 요청한다. 위험에는 발생 조건과 실제 관찰 범위를 적으며 근거 없이 빈도를 추정하지 않는다. 운영 내용은 P의 기존 문서/작업 기록에서 관리하고 공통 사본에 넣지 않는다.

기준으로 지정한 구현이 비활성이라는 근거 등 요구 전제와 모순되는 사실은 일반 차이가 아니라 **전제 충돌**로 보고한다. 확정 결정 변경은 사람 판단 규칙에 따르고, 그 전제에 의존하는 설계·구현만 멈춘다. 무관한 조사까지 일괄 중단하지 않는다. 사람 질문에는 사람이 사용하는 식별자와 코드 이름의 대응을 함께 제시한다.
