# SDD plan-change

## 계획 정정과 정책 전환

구현·검증 중 계획의 전제가 틀렸거나, 진행 중 작업에 적용할 프로젝트 정책이 바뀌면 다음 경로로 현재 지시를 정정한다. Small 이하는 Issue의 계획·기록을 사용하며 SDD나 별도 전환 문서를 만들지 않는다. 검토한 PLAN이라는 이유로 틀린 지시를 유지하거나 SUMMARY에만 차이를 숨기지 않는다.

새 산출물 배치의 AS-IS 정정은 `README.md`의 사람용 현황·위험과 `01-as-is.md`의 직접 근거 중 영향을 받는 원본을 모두 포함한다. 근거만 고치고 사람용 판단 전제를 과거 상태로 남기지 않는다.

1. 발견 근거와 영향을 받는 전제·Decision·계약·검증을 특정하고, 그 전제에 의존하는 편집·실행만 중단한다. 필요한 사실 조사와 독립적인 작업은 계속할 수 있다. 기존 허용 경계 밖 임시 테스트 작성도 자동 허용되지 않는다.
2. 확정 결정·제품 의미·범위·권한을 바꾸면 기존 사람 판단 규칙을 적용한다. 이미 내려진 결정이나 유효한 위임을 근거로 사용할 수 있으며 단순 사실 정정에 새 승인을 만들지 않는다. 위임 밖의 대안을 구현자가 임의로 선택하지 않는다.
3. 현재 Issue와 해당 AS-IS/TO-BE/change-plan의 잘못된 지시를 수정하고, 기존 기록에 이전 revision·대체한 문장/항목·변경 이유·근거와 결정 참조를 남긴다. 원래 revision은 이력으로 보존한다. 원문을 즉시 수정할 수 없다면 연결된 보정 문서/기록에 대체 대상과 새 지시를 명시하고 현재 계획의 진입점에서 이를 발견할 수 있게 한다. 그 연결을 권한·동시성 문제로 만들 수 없으면 영향 작업은 재개하지 않는다. 두 지시 중 무엇이 현재인지 구현자에게 추정시키지 않는다.
4. 정책 전환은 적용할 Issue·phase·시점과 대체되는 기존 정책을 기록한다. 활성 담당·실행 중 리뷰·미커밋 변경·최근 작업 기록을 확인하고 적용 구간을 조율한다. 이전 실행·검토는 당시 정책과 target의 기록으로 보존한다. 단순 문서 위치 이동은 의미 변경과 구분하며 이미 진행한 작업을 자동 초기화하지 않는다.
5. 현재 grade의 self/required review와 [의미·영향별 재검토](../design-review.md#의미영향에-따른-설계-재검토)를 적용한다. 기존 검토·검증 중 무효화된 근거와 유지 가능한 근거를 구분한다. 새 SHA나 정책 변경이라는 사실만으로 전체 A/B를 반복하지 않으며, 중요한 의미 변경을 문서 정정이라고 축소하지 않는다. 검증 입력이 바뀌면 [PASS 유효성](../verification.md#검증-시퀀싱과-pass-유효성)에 따라 해당 검증을 갱신한다.
6. 필요한 current-target 근거를 확보한 뒤 Issue·계획·Execution Packet의 참조와 적용 정책을 맞추고 해당 담당에게 인계해 재개한다. 종료 시에는 정정된 계획·실제 구현·검증의 일치를 확인한다.
