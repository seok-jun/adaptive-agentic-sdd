# 선택한 작업의 보호 규칙

이 시작본 W를 선택한 뒤에만 읽는다. 시작본이 그 작업에 유지하는 보호 규칙이며 제한을 추가할 뿐 권한을 주지 않는다. P의 기존 공통 규칙과 권한은 W 미선택 때도 적용된다. 팀은 자체 결정 절차로 공통 보호 규칙을 P에 별도 채택할 수 있다. 이 파일이 제품 AGENTS 구간을 생성하지 않는다.

- 무관한 사용자 변경을 보존한다. reset·checkout·clean·revert로 되돌리지 않는다.
- 비밀·자격 증명·보호 대상 개인정보를 개발 산출물에 넣지 않는다. P의 증거·공개 규칙을 따른다. 대화 로그를 복사하지 않으며 작업에 필요한 허용된 요구와 확정 결정만 남긴다.
- 파일·모듈·API·설정 이름은 실제 원본으로 확인하며 지어내지 않는다.
- 작업의 승인된 범위 안에서 수정한다. 무관한 리팩터링·이름 변경·포맷·의존성·기능을 추가하지 않는다. 수정 허용/금지 경계를 적용하며 금지가 우선한다.
- P의 모듈·통합 경계를 지킨다. 이 시작본의 lane 절차에서는 구현 경로 겹침이나 통합 전용 수정은 조율될 때까지 멈춘다.
- 실행하지 않은 테스트·빌드·lint·기기 검사를 PASS로 쓰지 않는다. 필수 실패·미확인·BLOCKED는 드러내며 요약만으로 완료로 바꾸지 않는다.
- 현재 실행 shell을 먼저 쓴다. 현재 shell 또는 portable 방식이 불가능할 때만 범위를 정한 다른 shell 대체를 쓴다.
- 다른 인코딩 근거가 없으면 저장소 텍스트는 UTF-8로 처음 읽는다. 깨진 출력으로 절차를 추론하지 않는다.
- 제품 작업 중 선택한 W snapshot을 유지한다. W 커스터마이징은 별도 프로젝트 소유 변경으로 하고 새 commit을 명시적으로 선택한다. 공개 원본의 승인은 필요하지 않다. 외부 적용 문서는 기존 생성물이 아니라 수정 가능한 원본이다.
- 사람이 하지 않은 결정을 만들거나 승인 조건을 낮추거나 위임을 생성·확대·확정하지 않는다. P의 실제 권한 원본을 따른다. 추가 방법론 판단 지점이 그 원본을 대체하지 않는다.
- 미결 사람 판단에 의존하는 작업만 멈추며 독립 작업은 계속할 수 있다. 질문할 수 없는 환경이면 의존 작업을 멈춘 채 선언 위치에 미결 질문을 남긴다.

선택한 시작본의 기본 제한이다. 프로젝트 소유자가 W를 발전시킬 수 있지만 Agent에게 제품 요구·예산·호스트 제한·사용자 결정을 면제할 권한이 생기지 않는다. 선택 입구의 로컬 채택 지원 문서는 그 방법론 범위에서만 따른다.
