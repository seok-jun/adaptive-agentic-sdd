# 최소 작업 방법론 (1.0 preview)

이 문서는 현재 프로젝트에 명시적으로 활성화해 쓰는 작업 방법론의 1.0 preview다. 효과는 아직 검증되지 않았고 구조가 바뀔 수 있다. 기존 공개 방법론(v0.2) 전체의 이관본이나 동등한 대체물은 아니다.

현재 호스트의 권한과 프로젝트의 제품 요구, 승인 조건, 쓰기 범위, 필수 검증을 먼저 따른다. 방법론은 새 권한·예산·모델 호출을 허가하지 않는다. 충돌을 해결할 수 없으면 활성화 또는 편집을 중단하고 근거를 남긴다.

1. 작업 목표와 현재 코드, 필요한 정보·실행 도구·검증 환경을 확인한다. 필요한 조건을 이미 알고 있는데도 실패할 때까지 기다리지 않는다.
2. 변경 전 관찰 가능한 짧은 파일·심볼·순서 목록에 요구의 적용 대상과 확인 방법을 연결한다. 기존 계획의 연결은 재사용하며 상세는 `supports/ordered-changes.md`를 따른다. 현재 preview의 기본 지원이며 단일 성공이나 모델 이름으로 제거하지 않는다.
3. 허용 범위에서 구현하고 프로젝트가 정한 검사를 실제로 실행한다. 과거 결과를 현재 실행의 PASS로 재사용하지 않는다.
4. 프로젝트가 승인하거나 기준으로 지정한 revision의 요구와 최종 변경·검사 증거를 대조한다. 빠진 적용 대상과 최종 검증의 축소·공백도 확인한다. 모델의 성공 판단과 실제 결과 채택은 별개다. 미검증, 구현 결함, 환경 장애, 원인 불명을 구별한다.

구체적인 작업 단위와 제품 사실은 프로젝트에서 관리한다. 모든 작업에 새 문서나 별도 계획 파일을 만들도록 요구하지 않는다. 이 방법론은 보안 경계나 자동 에이전트 실행기가 아니다.

## 사람 판단

1. 사람 판단이 필요한 미해결 질문이 생기면, 그 판단에 의존하는 작업을 멈추고 사람에게 묻는다. 의존하지 않는 작업은 계속할 수 있다.
2. 프로젝트는 사람이 판단하는 지점(예: 설계 단계 승인, 병합, 배포)을 자기 설정이나 작업 지침에 명시한다. 어느 지점을 몇 개 두고 어떤 방식으로 받을지는 프로젝트가 정한다.
3. Agent는 사람이 하지 않은 결정을 만들지 않는다. 리뷰 통과, 테스트 통과, 일반 진행 지시, 침묵을 사람의 결정으로 대신하지 않는다.

이 세 가지는 공통 최소 요건이다. 호스트·프로젝트 규칙은 이 요건을 더 엄격하게 할 수 있지만 면제하지 못한다. 충돌하면 그 판단에 의존하는 작업을 멈추고 사람에게 묻는다.

## 실제 적용과 개선 관측

작업을 수행하는 Agent가 기존 프로젝트 작업 기록에 아래 연결을 남긴다. 프로젝트가 정한 Issue·PR·인계 기록을 재사용하며, 별도 서비스나 전용 장부를 전제하지 않는다. 프로젝트의 시작·인계·종료 절차가 이 절을 소비해야 한다. 문서 배포나 사본 해시 확인 성공만으로 자동 수집·행동 준수를 주장하지 않는다.

프로젝트는 작업 기록의 기준 위치 하나와 이전 기록을 찾을 관계 기준을 정한다. 해당 작업의 시작 원본 하나에 고정 commit 또는 manifest hash와 읽은 문서 경로, 적용 구간, 보존 위치, 예정 지원을 남긴다. 이후 기록은 자기 작업의 시작 원본을 직접 참조하고 고정 정보의 본문 복사를 생략할 수 있다. 적용 정보가 바뀌면 변경 시점·새 값·구간을 표시하고 앞 구간을 소급 갱신하지 않는다. 이름만 있는 버전이나 나중에 해석할 수 없는 실행 ID만으로 원본을 대신하지 않는다. 이전 관측을 사용하면 원본과 이번 작업의 관계·선택 조치를 적고 없거나 찾지 못했으면 그 상태를 남긴다.

| 시점 | 남길 내용 |
| --- | --- |
| 적용 시작, 실제 변경 전 | 작업/실행 식별자, 읽은 고정 버전과 문서, 실제 적용할 지원과 구간, 관측을 보존할 프로젝트 위치. 이전 관측이 있으면 원본을 읽고 이번 작업에 관련되는 근거·조치를 연결한다. 없거나 조회 불가면 그 상태를 적는다. |
| 인계·중단 | 시작 원본 직접 참조, 현재 상태·수행한 지원·관측 근거, 미수집 항목과 이유, 다음 담당자가 이어 읽을 위치. 원본 접근 가능 여부와 인계 뒤 실제 읽기 여부를 구별해 기존 기록에 남긴다. 담당자가 바뀌어도 새 작업으로 초기화하거나 과거 구간을 소급 적용하지 않는다. |
| 구현 종료 및 작업 최종 종료 | 시작 원본 직접 참조, 실제 수행 지원과 계획과의 차이, 최종 요구–검증 결과·공백, 요구 누락·검증 실패·재작업·통제 발동/오탐·사람 개입의 관측과 근거, 사용 가능한 비용 출처와 범위, 수집 공백, `adaptation.md`의 다음 판단을 남긴다. 같은 결과가 기존 기록에 있으면 직접 참조한다. 기존 종료 기록을 갱신하거나 후속 기록으로 최종 상태를 보존하되 앞선 실패·당시 대상과 최종 보정을 구별한다. |

생략할 수 있는 것은 같은 정보의 본문 복사다. 새 실패·요구 미충족·검증 축소·출처 상실·다음 판단의 변경은 참조만으로 숨기지 않고 현재 요약에 드러낸다. 기록이 없다는 것을 변화 없음·0건·확인 완료로 해석하지 않는다. 작업이 바뀌면 시작 기록도 구별하며, 이전 작업이나 상위 작업의 실제 읽기 기록 재사용은 프로젝트 규칙을 따르고 원본·적용 관계를 표시한다. 새 작업의 읽기를 면제하거나 이전 작업의 비용·모델 관측을 상속시키지 않는다. 별도 공용 원장·복사본이나 무관한 과거 기록의 전수 재조회를 요구하지 않는다.

관측은 확인된 사실, 원인 가설, 미관측을 구별한다. `관측 없음`은 확인한 범위에서 해당 사건을 찾지 못했다는 뜻이며 작업 전체에서 0이었다는 뜻이 아니다. 출처가 없으면 `미수집`과 이유를 남긴다. 지표 하나가 없다는 이유로 나머지 관측을 생략하지 않는다. 요구·검사·변경·리뷰의 고정 commit 또는 원본 ID/링크를 사용하며, mutable 기록은 확인 시점과 대상 revision을 함께 적는다.

관측의 출처 유형(도구 결과·별도 검토·Agent 자기보고 등)을 구별한다. revision이 없는 mutable 기록은 원본 ID와 갱신 시각으로 식별하며, 갱신 시각도 없으면 변경 여부를 검증할 수 없다는 한계를 남긴다. 관측하지 못한 여러 항목은 같은 이유와 범위로 묶어 한 줄에 적을 수 있다. 항목별 빈 표나 전수 조사를 요구하지 않는다.

모델은 요청 설정과 실제 제공 정보의 출처를 구별한다. 종료 요약 등 작업 기록에는 확인된 요청 모델·요청 추론 설정과 각 출처를 남긴다. 실제 제공 모델·추론 설정을 확인하지 못했다는 이유로 확인된 요청값을 빼거나 `미확인`으로 바꾸지 않으며, 확인하지 못한 제공값만 `미확인`으로 둔다. 자기 보고·표시 이름을 적는 경우 그 출처로 표시하고 요청값이나 제공값으로 바꿔 적지 않는다. 역할·에이전트 식별자는 별도로 적고 모델 값 대신 쓰지 않는다. 비용은 host가 제공한 관측의 단위·실행 범위와 중복 관계가 확인되는 경우에만 사용한다. 누적값과 구간값, root와 worker, total과 cache/reasoning 하위 항목을 중복 합산하지 않는다. 미제공 비용·제공 모델·사람 시간을 추정하지 않는다. 프로젝트에 이미 있는 계측 표지가 있으면 그 출처를 다른 자료로 바꾸지 않는다. 출처·수집 가능 여부는 현재 구간에서 확인하고, 수집 한계가 시작 기록과 같으면 같은 이유·범위인 항목을 한 줄로 묶어 참조할 수 있다. 새 값·범위·변경된 한계는 명시한다.

기록과 필요한 비민감 근거는 작업 폴더를 정리하기 전에 프로젝트가 다시 조회할 수 있는 위치에 보존하고 재조회한다. 대화 원문·인용·재구성 가능한 요약, 비밀정보와 제품 사용자 데이터를 수집하지 않는다. 금지 자료를 보존하기 위해 새 저장 위치를 만들지 않는다. 시작 원본이 사라지거나 확인한 버전과 달라지면 참조만으로 적용 확인을 유지하지 않는다. 현재 직접 확인할 수 있는 적용 정보와 상실 범위를 기존 기록에 남기고, 이전 구간은 미확인으로 둔다. 출처 소실·조회 실패는 명시하며 요약·추정만으로 검증 사실을 복구하지 않는다.

적용 상태와 수집 상태는 별개다. 버전 읽기, 지원 실행, 관측 기록, 원본 재조회, 다음 판단으로의 전달을 각각 확인하고 미확인 단계를 드러낸다. 작업 중 도입한 경우 이후 구간만 부분 적용으로 기록한다. 수집 공백은 방법론 평가의 한계이며 프로젝트 완료의 새 gate나 승인 면제가 아니다.

### 발견한 문제의 기록과 프로젝트 연결

실행·검증·리뷰에서 요구 누락, 검증 공백, 실패, 불필요한 재작업 등 실제 문제를 발견한 경우에만 기존 작업 기록에 사건을 남긴다. 예상된 실패 테스트나 정상적인 설계 탐색을 자동으로 문제로 세지 않는다. 정상 단계의 행, 빈 사건 목록, `문제 없음` 보고, 전수 실행 추적은 추가하지 않는다. 기존 시작·인계·종료 의무는 유지하며 이 절은 문제 기록만 조건부로 추가한다. 별도 설계 문서가 없는 작업(예: 작은 작업)에도 같은 원칙을 적용하고, 기록을 위해 설계 문서를 만들지 않는다.

프로젝트 어댑터는 기존 설정이나 작업 지침에 **작업 식별 방법, 문제 기록 위치, 종료 요약 위치, 최종 종료 판정, 허용된 조회·쓰기 수단과 범위**를 연결한다. 별도 설정 파일이나 서비스를 요구하지 않는다. 종료 태그·댓글 표지·호스트 API는 공통 필수값이 아니다.

| 연결 예 | 문제 기록과 요약 | 종료·조회 |
| --- | --- | --- |
| 이슈 트래커 | 기존 작업 활동/댓글 → 작업 종료 요약 | 프로젝트의 최종 상태와 허용된 API/CLI |
| 로컬 문서 | 기존 작업 문서의 사건 부분 → 같은 문서의 종료 요약 | 프로젝트가 정한 완료 표시와 파일 경로/항목 참조 |

기존 기록 위치가 전혀 없으면 프로젝트가 작업별 최소 기록 위치를 먼저 지정하며, 첫 문제 발견 때만 그 사건 기록을 만든다. 위치·권한이 없거나 쓰기에 실패하면 기존 인계/종료 경로에 보존 실패와 확인 가능한 근거를 전달하고 기록 성공으로 보고하지 않는다. 임의 서비스 게시나 새 중앙 장부로 우회하지 않는다.

사건에는 작업과 사건을 구별할 기존 ID/원본 참조, 발생 단계(불명 허용)와 발견 단계, 수행 담당 역할/에이전트 식별과 발견 주체, 확인 가능한 모델·추론 설정과 출처, 관찰한 문제·근거, 조치·결과를 짧게 남긴다. 설정은 요청값과 host가 실제 제공한 metadata를 구분하며 미제공은 `미확인`이다. 모델명/추론 설정을 자기 추정하거나 발견자의 모델을 발생 담당자의 모델로 대입하지 않는다. 관측 사실과 원인 가설·귀속 불명을 분리하고 대화/추론 원문은 기록하지 않는다.

서브에이전트는 문제가 있을 때만 기존 반환 결과에 사건이나 원본 참조를 포함하고 상위 담당자가 보존한다. 같은 사건의 인계·재시도·수정·종료 요약은 원본 참조를 유지해 연결하며 최초 실패를 최종 성공으로 덮어쓰지 않는다. 서로 다른 발생을 같은 유형이라는 이유로 한 사건으로 합치지 않는다.

종료 담당자는 기록된 사건의 핵심 사실·담당 metadata·조치/결과와 원본 참조를 기존 종료 요약에 취합한다. 요약만 조회하는 어댑터에서도 사건이 보이도록 링크만 남기지 않는다. 작업 폴더나 임시 설계 문서를 지우기 전에 필요한 사실을 지속 보존 위치로 옮긴다. 승인된 설계 문서를 사건 장부로 수정할 필요는 없다. 종료 후 발견은 발견한 후속 작업에서 이전 작업을 연결하고 과거 종료 당시의 관측처럼 소급하지 않는다.

공개 배포 대상은 이 계약과 어댑터의 연결 방식이다. 프로젝트 사건·모델 사용 기록·근거를 공통 저장소에 자동 게시하거나 외부로 전송하지 않는다. 일반화한 공통 개선 후보를 공유할 때도 해당 프로젝트의 권한·정보 공개 범위를 따른다.
